# EchoTrace — Scenario, Question & Laboratory Framework

Each ET scenario is a practical Digital Forensic Technology exercise. The 100-scenario catalogue in `100_FORENSIC_SCENARIOS.md` is implemented through the following standard.

## Student scenario record
Each scenario must define:
1. **Incident situation** — fictional operational problem.
2. **Forensic objective** — the technical competency being trained.
3. **Evidence set** — artifacts the analyst must inspect.
4. **Investigation questions** — normally 5 questions; capstones may use 10–15.
5. **Practical laboratory** — acquisition, parsing, correlation, validation, reconstruction, or recovery work.
6. **Required deliverable** — professional artifact produced by the learner.
7. **Evidence standard** — artifact + record + timestamp + observation + inference + confidence + limitation.

## Difficulty progression
- ET-001–015: SQL & Database Forensics — Advanced/Senior
- ET-016–035: Windows, Filesystem & Identity — Senior
- ET-036–050: Memory & Network — Senior
- ET-051–070: Storage & Backup — Senior/Insane
- ET-071–085: Virtualization, Cloud & Automation/AI — Senior/Insane
- ET-086–099: Forensic Operations & Recovery Engineering — Senior/Insane
- ET-100: Full Enterprise Forensic Capstone — Insane

## Laboratory rule
No lab requires destructive malware, credential theft, unauthorized access, or attacks against live systems. SQL work is performed against synthetic training data or offline evidence. Recovery exercises use copies, validation datasets, and isolated environments.

## Solution rule
Instructor solutions must explain the forensic reasoning, not merely give an answer. Every solution should include expected evidence path, defensible conclusion, confidence, alternative explanation, common mistake, and recovery/response lesson.
